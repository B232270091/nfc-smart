# Биет NFC таг бэлтгэх

Платформ нь тогтмол HTTPS холбоос болон QR үүсгэнэ. Вэбсайт өөрөө биет NFC картыг бичихгүй. NFC бичих боломжтой утас/уншигч, NDEF URI record дэмждэг таг болон тохирох бичих апп шаардлагатай.

## Эхлээд платформ дээр

1. Өөрийн байгууллага, меню/танилцуулгын хуудсыг үүсгэнэ.
2. Page-г нийтэлнэ. Меню бол category идэвхтэй, бүтээгдэхүүн нийтлэгдсэн эсэхийг шалгана.
3. Dashboard → NFC карт хэсэгт нэр болон destination page сонгож карт үүсгэнэ.
4. Үүссэн **тогтмол картын холбоосыг** хуулна. Хэлбэр нь `https://YOUR_DOMAIN/t/<24-hex-code>`.
5. Нэвтрээгүй browser-оор холбоосыг нээж зөв хуудас харагдаж байгааг баталгаажуулна.

`/p/<slug>` нь тухайн public хуудасны холбоос. Destination-ийг дараа нь өөрчлөх боломжтой байлгахын тулд NFC тагт `/t/<code>` холбоосыг бичнэ. Production карт дээр localhost, түр preview домэйн эсвэл тестийн project URL бичихгүй.

## Тагт бичих

1. Төхөөрөмжийн NFC боломж болон тагтай нийцлийг шалгана. Android төхөөрөмжид шаардлагатай бол NFC-г асаана; унших/бичих цэг болон дэмжлэг нь төхөөрөмжөөс хамаарна.
2. NFC writer аппдаа шинэ **URL/URI** record сонгоно.
3. Dashboard-оос хуулсан HTTPS холбоосыг яг тэр хэвээр оруулна.
4. Write үйлдэл хийж картыг төхөөрөмжийн NFC хэсэгт хөдөлгөөнгүй ойртуулна. Аппын амжилттай бичсэн мэдэгдлийг хүлээнэ.
5. Аппаас гарч тагийг дахин уншуулахад browser дээр зөв public page нээгдэхийг шалгана.

Бичихэд URL-ийн эхлэл, hostname, `/t/` зам, бүтэн код алдаагүй байх ёстой. Таг хүрэлцэхүйц багтаамжтай, бичих хамгаалалтгүй байх шаардлагатай. Байнгын write-lock хийх нь буцаах боломжгүй байж болох тул өөрийн төхөөрөмжийн зааврыг дагаж, эцсийн production URL бүрэн баталгаажсаны дараа л шийднэ.

## QR fallback

Dashboard-оос тухайн картын QR-г татаж хэвлэнэ. QR нь картын тогтмол route-ийг ашиглаж destination өөрчлөгдөх боломжийг хадгална. QR tracking query нь эх үүсвэрийг ялгах зориулалттай; destination page-г hard-code хийхгүй.

QR-г зохих хэмжээтэй, contrast сайтай хэвлэж, бодит байрлуулах гэрэлтүүлэг болон зайд хоёр утсаар уншуулж шалгана. NFC болон QR хоёулаа public HTTPS сайт руу хандах тул интернет шаардлагатай.

## Гол acceptance test

1. Public меню дэх нэг бүтээгдэхүүний одоогийн үнийг тэмдэглэнэ.
2. Биет NFC картыг уншуулж уг үнийг харна.
3. Dashboard дээр бүтээгдэхүүний үнийг шинэчилнэ.
4. **Яг тэр картыг, дахин бичилгүйгээр** уншуулна.
5. Шинэ үнэ public menu дээр харагдах ёстой.
6. Картын destination-г өөр нийтэлсэн page рүү солино.
7. **Яг тэр карт** шинэ page-г нээх ёстой; картын код хэвээр байна.

Нээлт хуучин browser tab-д үлдсэн бол холбоосыг шинээр нээх эсвэл refresh хийнэ. Backend dynamic хүсэлт бүрд шинэ мэдээлэл авдаг; өмнө нээгдсэн дэлгэцэд realtime push шинэчлэлт хийхгүй.

## Алдаа оношлох

| Шинж | Шалгах зүйл |
| --- | --- |
| Таг огт уншихгүй | Төхөөрөмж NFC дэмждэг эсэх, NFC асаалттай эсэх, утасны унших цэг, таг/металл гадаргын нийцэл |
| URL буруу | Writer апп дээр тагийг read хийж production `/t/<code>` холбоостой харьцуулах |
| Хуудас олдсонгүй | Карт идэвхтэй, байгууллага идэвхтэй, destination нийтлэгдсэн эсэх |
| Зураг харагдахгүй | Server secret, private bucket, publication gate, upload төрөл/хэмжээ |
| Өөрчлөлт хуучнаараа | Production project зөв эсэх, өөрчлөлт хадгалагдсан эсэх, холбоосыг шинэ хүсэлтээр нээх |
| Хандалтын тоо нэмэгдэхгүй | Vercel trusted ingress, server key/HMAC secret, bot/rate limit нөхцөл; нэг минутын давтамж хязгаар байж болно |

HTTP analytics нь тагийг биетээр хүргэсэн эсэхийг нотлохгүй. QR, гараар нээсэн URL, дахин уншуулсан NFC холбоосууд бүгд web request үүсгэж болох тул тоог “хуудас нээлт” гэж уншина.
